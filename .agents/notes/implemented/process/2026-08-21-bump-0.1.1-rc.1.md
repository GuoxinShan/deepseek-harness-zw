# Agent Note: Fork baseline bump to 0.1.1-rc.1

Status: implemented

English | [中文](2026-08-21-bump-0.1.1-rc.1.zh.md)

## Problem

Upstream published `dsh-v0.1.1-rc.1`. The fork still sat on `0.1.0-rc.8` plus zw-layer patches (WKWebView `Content-Length`, MCP status events, session concurrent-writer guard, `web:log`, todo-completion guard, model-effort memory). Leaving the fork behind would mix official `^0.1.0-rc.8` packages with a later registry line and re-open unique-symbol / dual-module splits in the desktop runtime.

## Decision

`bump/0.1.1-rc.1` merges tag `dsh-v0.1.1-rc.1` and keeps every fork-only behavior:

- `frontend-static` takes the upstream miss contract (empty 404, no SPA fallback) and still sets `Content-Length` on 200 responses ([WKWebView note](../bug-fix/2026-08-18-wkwebview-bundle-content-length.md)).
- `client-modules` `serveBundle` `Content-Length` auto-merges onto the new `webserver/index-inject` boot path.
- Persistence concurrent-writer prose, MCP `mcp-client/status`, todo-completion-guard, and remembered reasoning effort stay.
- The fork-only `dsh-todo-completion-guard` version is aligned to `0.1.1-rc.1` because upstream release bumps do not touch it.

Desktop still consumes this fork through `runtime/revision.json` and `@crazx/*` zw publishes. Retargeting desktop is a separate consumer change after a `v0.1.1-rc.1+zw.N` tag exists.

## Alternatives considered

**Stay on rc.8 and cherry-pick vision / auth / 404.** Rejected: 172 first-parent commits, a credentials record API, and the index-injection rewrite would still have to land later, and desktop's `^0.1.0-rc.8` ranges already match `0.1.1-rc.1` on the official registry.

**Drop the WKWebView `Content-Length` now that missing paths 404.** Rejected: 404 does not change the index or bundle 200 path, which is the stall that blanks the desktop window.

## Consequences

Fork consumers keep the same local patches on a current upstream line. Desktop plugin test doubles that subclass `CredentialProvider` must implement the new record methods (`readRecord`, `describeRecord`, `listRecords`, `modifyRecord`, `deleteRecord`) before they typecheck against 0.1.1-rc.1. `GET /` remains 200, so the desktop sidecar ready probe is unchanged; History API pathname routes still need an explicit server rule.
