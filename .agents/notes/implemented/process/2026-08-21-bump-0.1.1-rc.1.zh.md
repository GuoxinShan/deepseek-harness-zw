# Agent Note: Fork 基线升到 0.1.1-rc.1

Status: implemented

[English](2026-08-21-bump-0.1.1-rc.1.md) | 中文

## Problem

上游发布了 `dsh-v0.1.1-rc.1`。fork 仍停在 `0.1.0-rc.8` 加 zw 层补丁（WKWebView `Content-Length`、MCP 状态事件、会话并发写守护、`web:log`、todo 完成守护、模型推理档位记忆）。继续停在 rc.8 会让官方 `^0.1.0-rc.8` 包与更新的 registry 线混装，并再次打开桌面 runtime 里 unique-symbol / 双模块实例分裂。

## Decision

`bump/0.1.1-rc.1` 合入标签 `dsh-v0.1.1-rc.1`，并保留全部 fork 专有行为：

- `frontend-static` 采用上游的未命中契约（空 404，无 SPA 回退），并继续给 200 响应设置 `Content-Length`（[WKWebView note](../bug-fix/2026-08-18-wkwebview-bundle-content-length.zh.md)）。
- `client-modules` 的 `serveBundle` `Content-Length` 自动合到新的 `webserver/index-inject` 启动路径上。
- 持久化并发写者说明、MCP `mcp-client/status`、todo-completion-guard、已记住的推理档位均保留。
- 仅 fork 拥有的 `dsh-todo-completion-guard` 版本对齐到 `0.1.1-rc.1`，因为上游发版 bump 碰不到它。

桌面仍通过 `runtime/revision.json` 与 `@crazx/*` zw 发布消费本 fork。把桌面钉到新基线是独立的消费方改动，前提是已有 `v0.1.1-rc.1+zw.N` 标签。

## Alternatives considered

**停在 rc.8，只摘视觉模型 / 鉴权 / 404。** 否决：172 个 first-parent 提交、凭证 record API 和 index 注入改写迟早还是要合，而且桌面的 `^0.1.0-rc.8` 范围在官方 registry 上已经能匹配到 `0.1.1-rc.1`。

**未命中项改成 404 后丢掉 WKWebView 的 `Content-Length`。** 否决：404 不改变 index 与 bundle 的 200 路径，而那才是把桌面窗口留成空白的卡住点。

## Consequences

fork 消费者在当前上游线上继续带着同一套本地补丁。桌面插件里继承 `CredentialProvider` 的测试替身必须实现新的 record 方法（`readRecord`、`describeRecord`、`listRecords`、`modifyRecord`、`deleteRecord`）才能对着 0.1.1-rc.1 通过类型检查。`GET /` 仍是 200，桌面 sidecar 就绪探测不变；History API pathname 路由仍需要显式服务器规则。
